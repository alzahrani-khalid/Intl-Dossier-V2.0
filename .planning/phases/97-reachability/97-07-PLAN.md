<objective>
Make the `/settings` subtree render navigation, by unifying the two checks that disagree about what
`/settings` means.

The bug, anchored: `AppShell.tsx:125` hides the global sidebar by PREFIX for anything starting
`/settings`, while `routes/_protected/settings.tsx:11-17` renders the settings nav only on an EXACT
match. Between those two readings, all six `/settings/*` children get no navigation at all.

**RULING-P97-03 §2 expands the population deliberately: this is a VIEWPORT MATRIX, not two call
sites.** `AppShell` gates BOTH Sidebar mounts — the desktop `aside` and the mobile drawer — off the
same flag, so a desktop-only fix would leave mobile settings children with no nav at all and would
look green in every oracle that only ever ran at 1400px. This plan closes across both halves; the
oracle proves both; silence on mobile would be a REJECT.

**The forbidden shape, named:** one predicate, one authored site. A second copy that happens to
agree today is the STAGE_TO_STATUS lesson — agreement by authorship is not agreement.

**And the comment is part of the bug.** `AppShell.tsx:121-124` asserts that SettingsLayout renders
its own nav column, which is exactly the claim that is FALSE for children. A fix that leaves that
comment standing hands the next reader the same wrong model.

Purpose: one meaning of "inside settings", honoured everywhere, at every width.
Output: one new predicate module with its test, and four consumers moved onto it.
</objective>

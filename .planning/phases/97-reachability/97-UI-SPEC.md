# Phase 97 — UI Design Contract

> Visual and interaction contract for Phase 97: Reachability. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. Sources: `97-CONTEXT.md` (D-01..D-13, all locked; no parks open),
> `97-RESEARCH.md` (per-surface anchors at HEAD `9c32c4db1`),
> `.tickmarkr/overseer/RULING-P97-01-ADMIN-DISPOSAL.md`, `frontend/DESIGN.md` (Linear spec,
> dark-canonical), `frontend/src/design-system/CLAUDE.md` (runtime token engine), and
> `96-UI-SPEC.md` / `95-UI-SPEC.md` / `93-UI-SPEC.md` (the inherited state vocabulary).
> Every component anchor below was read on disk 2026-08-17.

**Scope discipline — this phase adds NAVIGATION CHROME ONLY.** No new pages, no new visual
language, no new components, no new button variants, no layout redesign. Every pixel it puts on
screen comes from a component already shipped and already rendering elsewhere in the app; the
work is _registering_ entries in the ONE live source per surface and _mounting_ an existing nav
column at the right level. Linear dark is the only direction. The prototype at
`frontend/design-system/inteldossier_handoff_design/` is historical reference (superseded
2026-07) and nothing here points at it.

**The live-nav rule is load-bearing for this contract.** The rendering sidebar is
`components/layout/Sidebar.tsx` fed by `components/layout/navigation-config.ts`, mounted by
`AppShell.tsx:196` (desktop) and `:252` (mobile drawer). The `components/modern-nav/` tree
(`navigationData.ts`, `IconRail`, `NavigationShell`, `ExpandedPanel`) is mounted **only** by
`routes/modern-nav-standalone.tsx` and never renders in the product shell. **No contract in
this document is satisfied by an edit to `components/modern-nav/`.** An entry added there is a
data-structure claim, not a rendered affordance.

`getDossierRouteSegment` (`lib/dossier-routes.ts`, which already carries the 8th key).

```ts

  path: '/dossiers/elected-officials', icon: Crown }
```

- Renders through `SidebarNavItem` unchanged: 16px icon (`h-4 w-4`), 8px icon→label gap, 13px/400
  label at `--sidebar-ink`/.78, `var(--radius-sm)` row, `min-h-11` hit area, active state = 10%

- Label key `navigation.electedOfficials` EXISTS in both locales (`i18n/{en,ar}/common.json:147`)

**(b) Dossier hub type card — `pages/dossiers/DossierListPage.tsx` `DOSSIER_TYPES:75-83` → `DossierTypeStatsCard`.**

**(c) `/compare` — `routes/_protected/compare.tsx` validator + `EntityComparisonSelector.tsx:64-72`.**

- The widened union must stay a whitelist in `validateSearch` — an EO selection that the fetch arm

**(d) `/dossiers/create` — ZERO pixels.** `CreateDossierHub` has rendered 8 cards since

### NAV-02 — the `/settings` subtree renders navigation

**One predicate, two consumers** (`AppShell.tsx:125` prefix vs `routes/_protected/settings.tsx:14`
exact). Where it lives is planner discretion; the _rendered_ contract is fixed here:

- **Exactly ONE navigation affordance per settings page.** The global sidebar stays suppressed
  across the whole subtree (both consumers reading the same predicate), and the 240px settings nav
  column renders for index AND children. Two navs is as much a failure as none.
- **Reuse, do not rebuild.** The column is `SettingsNavigation` (`.settings-nav-card`) inside the
  `display:grid; grid-template-columns: 240px 1fr; gap: var(--gap)` geometry already in
  `SettingsLayout.tsx:60-64`. No second nav component, no restyle, no new width.
- **The index card-head does NOT travel with it.** `SettingsLayout`'s content card renders a
  `card-title`/`card-sub` derived from `activeSection` (`:85-91`) — index-only chrome. A child
  route wrapped in the full `SettingsLayout` would render another section's title above unrelated
  content: a lie. The shared piece is _grid + nav column_; the child route's own page component
  (`WebhooksPage`, `CalendarSyncSettings`, …) mounts unchanged in the content column.
- **Active-state contract (DOM-checkable).**
  - On `/settings` (index): exactly ONE `aria-current="page"` in the nav — the selected section, as
    shipped.
  - On any `/settings/*` child: **ZERO** `aria-current="page"` in the nav. None of the nine in-page
    sections is what is rendered, and three of them (`notifications`, `email-digest`,
    `integrations`) share a name with a _different_ child route — highlighting one would claim
    "you are here" about a page the user is not on.
- **No dead buttons.** From a child route, clicking a section row must land on `/settings` with
  _that_ section rendered. Recommended mechanism (planner discretion): a `?section=` search param
  on the `/settings` index, which also makes sections deep-linkable. Landing on the default
  `profile` after clicking "Appearance" is a forbidden shape.
- The shipped "Back to app" affordance (`data-testid="settings-back-to-app"`, chevron flipped in
  RTL) comes along with the column and becomes the return path on child routes too — this is a
  large part of what "renders navigation" means for the deepest child,
  `/settings/calendar/callback`.
- Responsive: below 768px the `@media (max-width: 768px)` block in `index.css:925-947` already
  collapses the grid to one column and turns the nav into a horizontal scrollable pill row with a
  `border-block-end` active marker. That behaviour must survive the remount unchanged — verify, do
  not re-author.
- Rows keep `minHeight: 44` (`SettingsNavigation.tsx:113`), `var(--radius-sm)`, hover
  `--line-soft`, active `--surface-raised` + 2px `var(--accent)` inline-start bar.

- Placement: the page header's actions region — `PageHeader` `actions` slot for pages that use it;
  for the four `ListPageShell` consumers (countries, forums, organizations, working_groups) either
  an optional `actions?: ReactNode` prop on `ListPageShell` rendered inside its existing
  `<header className="page-head">` (one edit, four consumers) or the existing `toolbar` slot.
  **Header-actions is the prescribed position** — it matches the EO model and keeps the toolbar for
  filter/search controls. Mechanism choice is planner discretion; the rendered position is not.
- Chrome: the shipped `Button` default variant = the `.btn-primary` recipe (fills `var(--accent)`,
  hover `var(--accent-hover)`, `var(--radius)`, no shadow, no scale, no glow). **No fourth button
  variant, no icon-only button, no split button, no dropdown.**
- Full-width below `sm`, auto width above — as the EO recipe does. `me-2` (logical) icon gap.
- Copy comes from the SHARED empty-state CTA key so the header button and the empty-state CTA say
  the same words on the same page (all eight keys exist in both locales — see Copywriting).
- **Condition-8 duty:** a page whose create flow is known-broken names that state in its decision
  row rather than silently linking to it. All eight `create.tsx` routes exist on disk; the audit
  graded all eight as rendering.

## RTL & Responsive Contract

- Logical properties only (`ms-*`, `me-*`, `ps-*`, `start-*`, `text-start`) — ESLint ERRORS on
  physical classes in `frontend/**`. Every reused component here is already compliant
  (`before:start-0`, `inset-inline-start`, `me-2`, `text-start`), so compliance is inherited by
  construction; new code must not break it.
- Directional icons flip via `className={isRTL ? 'rotate-180' : ''}`. In this phase only the
  settings "Back to app" chevron is directional (already handled, `SettingsNavigation.tsx:98`).
  `Crown`, `Plus`, `BarChart3`, `Gauge` are symmetric — no flip.
- Every surface renders under `dir="rtl"` with Tajawal applied (`?lng=ar` flips at first paint).
  The sidebar row, the settings column's inline-start accent bar, the tab bar's snap-scroll, and
  the create button's icon gap all mirror. Pixel-RTL sign-off stays an OPERATOR park — the
  contract requires the render, not the sign-off claim. **No visual baselines are committed**
  (D-12, the four-point calendar sign-off precedent).
- Desktop-primary: build at 1280px, verify at 1024px and 1400px. At 768–1023px the sidebar
  collapses to its icon rail (the new rows collapse with it — verify the EO row's icon is
  recognizable at rail width); the settings grid collapses to the pill row below 768px; the create
  button goes full-width below `sm`. Below 768px the app is read-only, so a create affordance
  there is decoration — it may render (as the EO recipe does today) but must not be the only path
  to anything.
- Touch targets: `min-h-11` / `minHeight: 44` are already on every affordance reused here.

# Phase 93 — UI Design Contract

> Visual and interaction contract for Phase 93: Failure Visibility. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. Sources: `93-CONTEXT.md` (D-03..D-08 are the UI-binding decisions),
> `frontend/DESIGN.md` (Linear spec, dark-canonical), `frontend/src/design-system/CLAUDE.md`
> (runtime token engine), and the shipped components under `frontend/src/components/`.

**Scope discipline:** this is NOT a new-feature phase. It adds THREE render states to surfaces that
already exist, plus one copy rule. No new pages, no new navigation, no new layouts, no new button
variants. Linear dark is the only direction; `frontend/design-system/inteldossier_handoff_design/`
is historical reference (superseded 2026-07) and nothing here points at it.

| #   | State                           | Decision  | Surfaces                                                                                                                                                                                                                                                                                                                            |

| 1   | Query-error state (shared)      | D-03/D-04 | `routes/_protected/admin/field-permissions.tsx`, `routes/_protected/admin/data-retention.tsx`, Tag Analytics (`routes/_protected/tags.tsx`), position attachments section, `routes/_protected/delegations.tsx`, `/tasks/queue` (`pages/AssignmentQueue.tsx`), analytics dashboard widgets (`hooks/useWidgetDashboard.ts` consumers) |

| State     | Semantic color          | Icon               | Announcement    | Primary affordance        |

## Component Contracts

### 1. QueryErrorState — one shared component (D-03)

**Closest existing components:** `components/ui/alert.tsx` (the only general-purpose alert
primitive — destructive variant is already token-correct: `border-[var(--danger)]`,
`bg-[var(--danger-soft)]`, `role="alert"` built in) and
`components/empty-states/EmptyState.tsx` (the layout vocabulary for centered
icon/title/description/action). The error component composes these two patterns; there is no shared
query-error component in the tree today — that absence is the defect class.

**Location:** `frontend/src/components/error-states/QueryErrorState.tsx` (kebab-case folder,
PascalCase file — matches the ESLint per-directory case rules). Internal prop shape is planner/executor
discretion per 93-CONTEXT "Claude's Discretion"; the two variants and everything visual below are the
contract.

**Variant A — page-level** (whole route's primary query failed: field-permissions, data-retention,
delegations, tasks/queue, tags page when the page query fails):

- Centered in the content region, `max-w-md`, vertical padding 48px (`py-12`), horizontal 16px.
- Icon: `AlertCircle` at 32px (`size-8`), color `text-danger`, inside a 64px (`size-16`) circle
  washed `bg-danger/10` (opacity modifier on the base token, per the Linear recipe rules — the
  `--*-soft` literals are not `@theme` utilities).
- Title: 16px / weight 600 / `text-ink` — "Unable to load data" (key below).
- Body: 13px / weight 400 / line-height 1.5 / `text-ink-mute`, `text-start`-safe (centered block).
- Retry: one `.btn-primary` labelled "Try again", no icon. The single accent element of the state.
- Wrapper carries `role="alert"`. No card border when standing directly in the content region; when
  the region is a card, the card keeps its normal `1px solid var(--line)` chrome — the state never
  adds a second border, shadow, or gradient.

**Variant B — inline** (a region inside a page: position attachments section, Tag Analytics card,
each analytics-dashboard widget):

- Composes `Alert` destructive as shipped in `components/ui/alert.tsx`: `1px solid var(--danger)`,
  `bg-[var(--danger-soft)]`, radius `var(--radius)` (8px), padding 16px (`p-4`), icon `AlertCircle`
  at 16px (`size-4`) start-positioned (`start-4`, already logical in the recipe).
- One-line message at 13px; retry as `.btn-ghost` at the inline-end. Accent is NOT used inline —
  ghost keeps danger the only non-neutral inside cards.
- `role="alert"` (inherited from the Alert primitive).
- The inline variant never exceeds the height of the content it replaces; it does not stretch to
  fill an empty card.

**Which variant where:** the region that OWNS the failed query gets the state. Page's primary
query → variant A replacing the page body. A widget/section query → variant B replacing only that
widget/section; sibling widgets that succeeded render normally.

**Small numeric chrome** (tab counts, count badges fed by `useDossier.ts:683/738`,
`useWidgetDashboard.ts` stat numbers): a failed count never fakes `0`. It renders an em dash `—`
with `aria-label` from `common:errors.countUnavailable`; the nearest owning region shows variant B.
No bespoke mini-error UI for badges.

**Retry semantics:** the retry button calls TanStack Query `refetch()` on the failed query (or the
region's query group). While refetching, the button is disabled (`aria-disabled`), label unchanged —
no spinner redesign, no optimistic clearing of the error until the refetch settles. A second failure
re-renders the same state (no escalation UI).

### 2. Page-level not-found (D-05/D-06)

**Mechanism:** TanStack Router `notFound()` — the precedent already in the tree. The boundary is
`routes/__root.tsx` `NotFoundPage` (`notFoundComponent`, line 72); `positions/$id.tsx`,
`after-actions/$afterActionId.tsx`, and `engagements/$engagementId/after-action.tsx` already throw
it. Dossier detail, engagement detail, and report builder adopt the same throw. No fourth invention.

**Visual contract = the existing root `NotFoundPage`, unchanged:** full-viewport centered block,
oversized `404` numeral, "Page not found" heading, description, and three nav actions (Go back /
Dashboard / Search). It renders at the root boundary — outside the app shell — which is the shipped
behavior for `positions/$id` and is acceptable per D-06. Its copy keys (`common:errors.pageNotFound`,
`common:errors.pageNotFoundDescription`) already exist in both `en` and `ar`. Restyling its legacy
`text-muted-foreground` classes is OUT of this phase's scope (surgical-change rule); record-specific
copy ("Dossier not found") is a permitted refinement via a per-route `notFoundComponent` but is not
required by this contract — the required bar is: well-formed absent ID → `notFound()` → this page,
never the error state, never skeletons that resolve to "Check your connection".

**No retry on not-found.** Retry is meaningless for a record that is not there; the affordances are
navigational only. This asymmetry (error retries, not-found navigates) is a deliberate discriminator.

### 3. Degraded / incomplete-record state (D-07)

An engagement whose `engagement_dossiers` extension row is missing renders:

- **Identity first:** the page header with whatever identity the base record supplies (name/title,
  type badge) — never a chrome shell with an empty title.
- **A named callout** directly below the header, full content width: `Alert` DEFAULT variant
  (`border-[var(--line)]`, `bg-[var(--surface)]`) with an `AlertTriangle` icon overridden to
  `text-warn` — warn, not danger, because nothing failed; the record is incomplete. Title
  "Incomplete record" at 16px/600; description at 13px/400 `text-ink-mute`. Wrapper `role="status"`
  (persistent informational state, not an interruption). No new Alert variant is added — the icon
  color override on the default variant is the whole delta.
- **Dependent sections suppressed:** sections that cannot render without extension data are omitted,
  not rendered as empty states with create CTAs (which would be a second confident lie). The callout
  is the single explanation.
- No retry (the data is absent, not failed) and no accent.

### 4. Copy rule — no internal strings (D-08, criterion 5)

- No user-facing error renders a stack trace, SQL, a PostgREST/Postgres code, or a raw
  `error.message` originating from a query/transport rejection. `pages/AssignmentQueue.tsx:48`'s
  `{error.message || t('queue.error')}` is the exemplar defect: the fallback key is right, the
  first operand must go.
- The shared component renders i18n copy ONLY, with one structured exception: a server error body
  that carries the project's bilingual envelope (`message_en` / `message_ar` — the shape
  `data-retention` already returns) MAY be rendered, selecting by current language. `error.message`,
  `details`, `code`, and any other field never reach JSX.
- React Hook Form field-validation messages are author-written user-facing copy and are OUT of this
  rule's population (D-08's partition).
- Diagnostics go to `console.error` (production-safe per the frontend logging convention), never to
  the DOM.

## Loading → Error Transition (the "24 skeletons" contract)

Criterion 3's complaint is a wall of skeletons resolving to a wrong message. The contract:

- **Skeleton renders only while `isLoading`** (initial fetch, no cached data). The instant a query
  settles as `isError`, the skeleton region is replaced by the error state (or by `notFound()` for
  an absent record) — no intermediate empty render, no confident-empty flash.
- **Skeleton count is bounded by the destination layout:** at most ONE composed skeleton per region
  — a `SkeletonTable` capped at 8 rows, or at most 3 `SkeletonCard`s (primitives from
  `components/ui/skeleton.tsx`). Never a grid of dozens.
- **Retry policy bounds skeleton duration:** queries on this phase's surfaces do not retry 4xx
  responses (a 404 becomes `notFound()` after ONE round-trip — the not-found page appears in
  single-request time, not after a retry storm); network errors and 5xx retry at most 2 times, so
  the skeleton yields to the error state in bounded time (worst case a few seconds of backoff, not
  the TanStack default 3-retry exponential tail).
- The skeleton itself stays neutral (existing primitive, `--surface-raised` shimmer) — it never
  previews danger color.

## Spacing Scale

Declared values (multiples of 4 only) — the scale the new states compose from:

| Token | Value | Usage in this phase                                  |
| ----- | ----- | ---------------------------------------------------- |
| xs    | 4px   | icon-to-text gaps inside the inline alert            |
| sm    | 8px   | stacked text gaps (title → description)              |
| md    | 16px  | alert padding (`p-4`), horizontal page-state padding |
| lg    | 24px  | description → retry button gap                       |
| xl    | 32px  | page-level icon size                                 |
| 2xl   | 48px  | page-level state vertical padding (`py-12`)          |
| 3xl   | 64px  | page-level icon circle                               |

Exceptions: `12px` / `20px` / `52px` — the inherited density tokens `--gap` (compact) / `--pad`
(padInline, comfortable) / `--row-h` (comfortable) from
`design-system/tokens/densities.ts`. They are pre-existing engine values the surrounding chrome is
built on, not new declarations of this phase; any table/list row an error state sits inside keeps
obeying `var(--row-h)`.

**Stated as a population, per `P93-UI-CHECK-1.md` Dimension 5:** none of the three new states —
`QueryErrorState` (page-level or inline), the not-found render, or the degraded callout — introduces
a `12` / `20` / `52` value of its own. Every occurrence belongs to chrome that already surrounds
them. So the declared scale `{4,8,16,24,32,48,64}` is exhaustive over what this phase authors, and
the Exceptions line is exhaustive over what this phase inherits.

`frontend/src/index.css` (`--t-body: 13px`, `--t-meta: 12px`, `--t-card-title: 16px`,
`--t-page-title: 28px`; `--font-normal: 400`, `--font-semibold: 600`):

| Role    | Size | Weight | Line Height |

| Label   | 12px | 400    | 1.4         |
| Heading | 16px | 600    | 1.2         |
| Display | 28px | 600    | 1.2         |

The mono label sizes (`--t-label: 10.5px`, ~11px mono chrome) and the KPI value (`--t-kpi-value:

## Color

Dark-canonical literals from `PALETTES.linear` (`design-system/tokens/directions.ts`) — shown for
reference only; implementation uses `var(--*)` tokens / `@theme` utilities EXCLUSIVELY (raw hex is
an ESLint error outside the three byte-matched token copies). Light mode derives automatically.

| Role            | Value (dark)                                                                            | Usage                                                        |
| --------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Dominant (60%)  | `--bg` `#010102`                                                                        | page canvas behind every state                               |
| Secondary (30%) | `--surface` `#0f1011` / `--surface-raised` `#141516`                                    | cards and regions the states render inside; skeleton shimmer |
| Accent (10%)    | `--accent` `#5e6ad2`                                                                    | see reserved list                                            |
| Destructive     | `--danger` `#e86154` (wash `bg-danger/10` / `var(--danger-soft)` via the shipped Alert) | error-state icon + inline alert chrome ONLY                  |

these states (shadow stays reserved for drawers); no gradients; radii `var(--radius-sm/-/lg)` =
6/8/12 only.

## Copywriting Contract

All strings are i18n keys in the EXISTING `common` namespace (`frontend/src/i18n/en/common.json` +
`frontend/src/i18n/ar/common.json`, under the existing `errors` object) — already registered in
`src/i18n/index.ts` for both languages, so no new-namespace registration risk (an unregistered
namespace silently falls back to English in BOTH languages). Address with the COLON form:
`t('common:errors.queryFailed.title')` — dot-form namespace addressing leaks raw keys. Sentence
case; no emoji; no marketing voice; no exclamation marks.

| Element                  | Copy                                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| Primary CTA              | Try again (`common:errors.retry`)                                                                                             |
| Error state heading      | Unable to load data (`common:errors.queryFailed.title`)                                                                       |
| Error state body         | The request failed. Try again, and contact an administrator if it keeps failing. (`common:errors.queryFailed.description`)    |
| Inline error (one line)  | Unable to load this section. (`common:errors.queryFailedInline`)                                                              |
| Count placeholder label  | Count unavailable (`common:errors.countUnavailable`)                                                                          |
| Not-found heading        | Page not found (`common:errors.pageNotFound` — EXISTS, reused)                                                                |
| Not-found body           | The page you are looking for does not exist or has been moved. (`common:errors.pageNotFoundDescription` — EXISTS, reused)     |
| Degraded heading         | Incomplete record (`common:errors.incompleteRecord.title`)                                                                    |
| Degraded body            | This record is missing its linked dossier data. Some sections cannot be shown. (`common:errors.incompleteRecord.description`) |
| Empty state              | unchanged — the existing `EmptyState` vocabulary already covers genuine emptiness; this phase adds no empty-state copy        |
| Destructive confirmation | not applicable — this phase has no destructive actions                                                                        |

Arabic strings (executor aligns terminology with the existing `engagements`/`dossiers` namespace
glossary before committing; these are the contract's suggested renderings):

| Key                                   | ar                                                                |
| ------------------------------------- | ----------------------------------------------------------------- |
| `errors.retry`                        | إعادة المحاولة                                                    |
| `errors.queryFailed.title`            | تعذر تحميل البيانات                                               |
| `errors.queryFailed.description`      | فشل الطلب. حاول مرة أخرى، وإذا استمرت المشكلة تواصل مع المسؤول.   |
| `errors.queryFailedInline`            | تعذر تحميل هذا القسم.                                             |

## RTL & Responsive Contract

- Logical properties only (`ms-*`, `ps-*`, `start-*`, `text-start`) — the shipped Alert recipe is
  already logical (`[&>svg]:start-4`, `ps-7`); the new component inherits that. ESLint errors on
  physical classes.
- `AlertCircle` and `AlertTriangle` are symmetric — no RTL icon flip. The retry button carries no
  icon, so no flip case exists in the new states.
- Verified at 1024px and 1400px (the analyst-workstation widths): page-level states center within
  the content region at both; inline states never overflow their card. Below 768px the app is
  read-only — the states render unchanged (they are read-only by nature); the retry button meets the
  44px touch target there via the existing `min-h-11` mobile pattern.
- Rendered with `dir="rtl"` and verified that Tajawal applies (`?lng=ar` flips at first paint for
  visual checks).

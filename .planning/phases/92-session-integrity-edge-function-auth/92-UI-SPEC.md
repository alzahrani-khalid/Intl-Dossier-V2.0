# Phase 92 — UI Design Contract

> Visual and interaction contract for Phase 92 (Session Integrity & Edge-Function Auth).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** This phase has exactly three UI surfaces, all settled by
`92-CONTEXT.md` locked decisions:

1. The sidebar user card becomes a working dropdown by **mounting the existing `NavUser`**
   (`frontend/src/components/layout/nav-user.tsx`) — AUTH-01, D-01. A mount, not a build.
2. `/settings` gains a **sign-out control** in its Security section — AUTH-05, D-02.
3. `/delegations` gains an **error state** visually and semantically distinct from its
   empty state — AUTH-04, D-13.

AUTH-02 (edge functions) has **no UI surface**. AUTH-03's forced redirect is a **plain
navigation to `/login`** — no return path (D-12, operator-decided), **no toast, no
interstitial, no "session expired" modal**. `/login` itself is out of this phase's
`files_modified`.

Design source of truth: `frontend/DESIGN.md` (the Linear spec) and
`frontend/src/design-system/CLAUDE.md` (the runtime token engine). **Linear dark is the
only direction.** The prototype at `frontend/design-system/inteldossier_handoff_design/`
is historical reference, superseded 2026-07 — nothing here points at it.

## Spacing Scale

Declared values (8-point scale, multiples of 4 only):

| Token | Value | Usage in this phase                                                                      |
| ----- | ----- | ---------------------------------------------------------------------------------------- |

existing `py-1.5`); this phase mounts existing chrome and declares no new off-scale

## Color

Dark mode is canonical; light values are the derived, AA-proven pairs from
`frontend/DESIGN.md`. **All values reach code as `var(--*)` tokens or `@theme`-mapped
utilities (`bg-bg`, `text-ink`, `border-line`, `text-danger`…) — raw hex is an ESLint
error.** Hex below is documentation of what the tokens resolve to in dark mode.

| Role            | Value (dark)                                                                                                                   | Usage                                                                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| Dominant (60%)  | `--bg` `#010102`                                                                                                               | Canvas behind everything                                                               |
| Secondary (30%) | `--surface` `#0f1011` ladder (`--surface-raised` `#141516`, `--surface-3` `#18191a`, `--surface-4` `#191a1b`) + `--sidebar-bg` | Cards, sidebar, topbar; the NavUser dropdown menu sits on `--surface-3` (popover tier) |
| Accent (10%)    | `--accent` `#5e6ad2`                                                                                                           | See reserved list below                                                                |
| Destructive     | `--danger` `#e86154` (light: `#be241f`)                                                                                        | See reserved list below                                                                |

Accent reserved for: focus-visible rings (`--focus-ring`), the sidebar avatar-initials
disc (existing chrome, kept), the single `.btn-primary` "Try again" CTA in the
`/delegations` error state, and active nav states. Nothing else in this phase.

Danger reserved for: the `/delegations` error-state icon (`text-danger`) and its soft
wash (`bg-danger/10` — opacity modifier per the recipe rules, never a `-soft` utility).
**The sign-out controls are NOT danger-styled**: signing out is a session end, not data
destruction, and the existing `NavUser` item is a plain ink menu item — the `/settings`
control matches it. No destructive confirmation dialogs exist in this phase.

Elevation: flat surfaces, `1px solid var(--line)` borders (`--line-strong` for
emphasis), no card shadows, no gradients. The dropdown menu gets popover treatment
(`--surface-3`, `1px solid var(--line)`, `--radius` 8px). Radii only from
`--radius-sm`/`--radius`/`--radius-lg` (6/8/12).

## Copywriting Contract

Voice rules (checker Dimension 1): sentence case for titles and buttons; no emoji; no
marketing voice ("Discover", "Easily", exclamation marks, first-person plural are
banned); errors state the problem plus the next step and **never leak internals** (no
raw supabase-js strings — `/tasks/queue` doing that is a named milestone defect).
**Every new string ships in English and Arabic in the same edit** — the i18n bundle is
static (`src/i18n/index.ts`); a missing key silently falls back to English in both
languages.

| Element                                    | Copy (EN)                                                                                                                 | Copy (AR)                                                                       |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Sign-out menu item (NavUser + `/settings`) | Sign out                                                                                                                  | تسجيل الخروج                                                                    |
| `/settings` session group title            | Session                                                                                                                   | الجلسة                                                                          |
| `/settings` sign-out description           | End your session on this device.                                                                                          | إنهاء جلستك على هذا الجهاز.                                                     |
| `/delegations` error heading               | Couldn't load delegations                                                                                                 | تعذر تحميل التفويضات                                                            |
| `/delegations` error body                  | Your delegations couldn't be retrieved. Try again — if the problem continues, sign in again.                              | تعذر استرجاع تفويضاتك. حاول مرة أخرى، وإذا استمرت المشكلة فسجّل الدخول من جديد. |
| Error-state retry CTA                      | Try again                                                                                                                 | حاول مرة أخرى                                                                   |
| Destructive confirmation                   | none in this phase (sign-out is one click on both surfaces, matching the existing `NavUser` item; no confirmation dialog) | —                                                                               |

Key placement (exact key names are the planner's call; the copy above is the contract):

- **`common:navigation.logout` is currently MISSING from both `common.json` files.**
  `nav-user.tsx:94` calls `t('navigation.logout', 'Logout')`, so as built it renders
  the inline fallback "Logout" in BOTH languages. This phase adds the key to
  `src/i18n/en/common.json` and `src/i18n/ar/common.json` with the copy above
  ("Sign out" supersedes the "Logout" fallback — it matches the requirement's own verb
  and the existing `settings:security.signOutConfirm` phrasing).
- `/settings` strings live in the `settings` namespace under `security.*`, beside the
  existing `signOutConfirm` / `sessionTimeoutDesc` keys.
- `/delegations` error strings live in the `delegation` namespace under `list.error.*`,
  beside the existing `list.empty.*` / `list.emptyDescription.*` keys. Arabic reuses
  the bundle's established noun (تفويضات).

## Surface Contracts

### 1. Sidebar user card → `NavUser` mount (AUTH-01, D-01)

The work is to **mount** `frontend/src/components/layout/nav-user.tsx` — a complete
dropdown (avatar, Profile → `/settings`, Settings → `/settings`, Sign out via
`useAuth().logout()` at line 92) currently imported by zero files. Do not design a new
component. The static user card at `frontend/src/components/layout/Sidebar.tsx:101-114`
is today's non-interactive placeholder; the mounted control replaces or wraps it while
**keeping its visual identity**: accent avatar disc with initials, two-line
name + role, the existing `--radius-sm` card wash on `--sidebar-bg`.

`frontend/src/components/layout/header/UserMenu.tsx` is a second, functionally
identical orphan. **Only one menu gets mounted** (NavUser, per D-01); two logout menus
is a worse outcome than one orphan. Deleting `UserMenu.tsx` is planner's discretion.

States:

| State         | Contract                                                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default       | Reads as the existing sidebar user card (name + role, avatar disc). No new chrome.                                                                                                                              |
| Hover         | Background eases toward the existing card wash — a fade, never a lift or shadow.                                                                                                                                |
| Open          | Menu on `--surface-3`, `1px solid var(--line)`, `--radius` (8px), width ~224px (`w-56` as built). Items: identity label, separator, Profile, Settings, separator, Sign out. Sign out is plain ink — not danger. |
| Focus-visible | Ring in `--accent`, never opacity-only (recipe rule).                                                                                                                                                           |
| RTL           | Menu opens on the logical end side — `nav-user.tsx:60` already flips `side` on `isRTL`. Tajawal applies to all labels; verify rendered `dir="rtl"`.                                                             |
| Activation    | Sign out calls the existing `logout()`; user lands on `/login` with the session cleared (D-04 — clearing asserted, not assumed).                                                                                |

Note for the executor: `NavUser` as built uses shadcn-idiom classes
(`bg-sidebar-accent/50`, `text-muted-foreground`, `focus-visible:ring-ring`) that
resolve through the `@theme` mapping. If any resolve visibly off-token against the
sidebar, correct via tokens — no new variants, no raw hex. It also calls
`useSidebar()` from `components/ui/sidebar`; if the live `Sidebar.tsx` (which does not
use that provider) can't supply it, the mount adapts the consumer, not the shell.

### 2. `/settings` sign-out control (AUTH-05, D-02)

A second, **independent** sign-out surface — it must work even if the sidebar mount
regresses. Closest existing component (matched per the no-questions rule):
`frontend/src/components/settings/sections/SecuritySettingsSection.tsx`, which already
composes labelled `SettingsGroup` rows. Add a "Session" group with one row: label
"Sign out", Meta-size description, and a button on the end side.

- Button recipe: `.btn-ghost`/secondary — **not** `.btn-primary` (reserved for save
  actions on this page) and **not** danger. One click, no confirmation, lands on
  `/login`.
- Row geometry matches the section's existing rows: `1px solid var(--line)`
  separations, logical properties (`ms-*`/`ps-*`/`text-start`) throughout.
- AUTH-05's reachability half is satisfied by D-01's mount (`NavUser` links to
  `/settings` twice). The `/settings/*` children-render-without-nav defect is `NAV-02`,
  a later phase — **out of scope here** (D-03 scope fence).

### 3. `/delegations` error state (AUTH-04, D-13)

The page (`frontend/src/pages/delegations/DelegationManagementPage.tsx`) currently
destructures only `data, isLoading, refetch` from `useMyDelegations` — a rejected query
is indistinguishable from an empty one and renders "You haven't granted any
delegations" (`src/i18n/en/delegation.json:20`) over zeros. The whole milestone is
about failure not rendering as emptiness, so ERROR must be distinct from EMPTY on
every axis:

| Axis        | EMPTY (existing, unchanged)                                                                          | ERROR (new)                                                                                                                              |
| ----------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Icon        | Neutral: `text-ink-faint` on `bg-surface-raised` circular wrapper (`DelegationList.tsx:79-81` idiom) | `AlertTriangle` (already imported by the page) in `text-danger` on a `bg-danger/10` circular wrapper — same geometry, opposite semantics |
| Heading     | "You haven't granted any delegations"                                                                | "Couldn't load delegations" — names the failure                                                                                          |
| Body        | Onboarding guidance                                                                                  | Problem + next step (copy contract above). Never the raw error string.                                                                   |
| Action      | none                                                                                                 | "Try again" `.btn-primary` wired to `refetch`                                                                                            |
| Semantics   | plain region                                                                                         | `role="alert"` on the error container — the established repo pattern for forced-error verification                                       |
| Stats cards | real counts                                                                                          | **Em-dash `—`, never `0`** — a failed query must not report a confident zero                                                             |
| Tabs        | per-tab empty copy                                                                                   | The error state replaces the list area of **both** tabs (one failure, one message)                                                       |

Layout geometry mirrors the shared `EmptyState` component
(`frontend/src/components/empty-states/EmptyState.tsx`: centered column, `py-12`,
circular icon wrapper, Heading/Body scale) so error and empty read as siblings, not
strangers. Whether the planner extends `EmptyState` with a tone/variant or builds a
sibling `ErrorState` on the same geometry is an implementation choice; the rendered
contract above is fixed. The `my-delegations` **auth** half is closed by the AUTH-02
edge-function migration; this surface only owes the honest rendering. The general
repository-layer fix is `TRUST-01` (Phase 93) — do not pre-empt it here.

# Phase 96 — UI Design Contract

> Visual and interaction contract for Phase 96: Real Numbers. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker. Sources: `96-CONTEXT.md` (D-01..D-23, all locked; PARK-96-01 open),
> `frontend/DESIGN.md` (Linear spec, dark-canonical), `frontend/src/design-system/CLAUDE.md`
> (runtime token engine), `95-UI-SPEC.md` / `93-UI-SPEC.md` (the inherited state vocabulary), and
> the shipped components at the pinned seams (`96-CONTEXT.md` §The seams, pinned).

**Scope discipline:** this phase makes numbers, charts and trends TRUE. It introduces one new
visual element (the COUNT-04 overdue badge on kanban cards) and one new page state (the DEAD-05
honest-disable branch, if research takes it); everything else is state-truthfulness inside
existing chrome. No new pages, no new navigation, no new layouts, no new button variants, no
redesign of any surface it touches. Linear dark is the only direction;
`frontend/design-system/inteldossier_handoff_design/` is historical reference (superseded
2026-07) and nothing here points at it.

| State          | Semantic color                                 | Icon                         | Announcement          | Primary affordance        |

## Component Contracts

### 1. DEAD-05 — `/analytics`: real data or honest disable (D-03)

**Seam:** `routes/_protected/analytics.tsx` → `pages/analytics/AnalyticsDashboardPage.tsx`.
The page already wires `QueryErrorState` (`:269-275`), `MetricsGridSkeleton`/`ChartSkeleton`
loading, HeroUI tabs, and recharts charts. The fabrication class DEAD-05 names lives in
`components/analytics/AnalyticsPreviewOverlay.tsx` (`preview.insightsYouWillGain`, `:159`) and
the `generateSample*` sample-data mode (`AnalyticsDashboardPage.tsx:44-49, :173-196`).

The branch (real vs disabled) is decided by RESEARCH feasibility per widget and RECORDED in the
plan text (D-03). Both branches are contracted here so the contract is invariant under the
decision:

**Branch A — real data.** The four summary cards and four charts render real backend data.

- Charts keep their shipped recharts chrome: flat fills, no gradients (`frontend/DESIGN.md`
  §Don't), series colors from the existing chart-palette carve-out tokens (the ESLint hex
  carve-out for chart palettes, `frontend/CLAUDE.md`), grid/axis lines in `var(--line)`.
- The sample-data mode (`generateSampleAnalyticsSummary` et al.) and the
  `AnalyticsPreviewOverlay` "Insights you'll gain" pitch DO NOT render on any widget whose real
  data path works — fabricated sparklines/donuts over live chrome is the forbidden shape even
  as an opt-in, because the register names the copy itself (`REQUIREMENTS.md:91`). If a subset
  of widgets stays unreal, EACH unreal widget renders the honest-disable state (Branch B,
  region-scoped), never the preview overlay.
- Summary-card deltas follow the DEAD-06 trend rule below: a delta renders only from a
  completed comparison.
- Loading/error contracts unchanged: content-aware skeletons while `isLoading`;
  `QueryErrorState` variant A on page-level `isError` (already shipped); no redesign.

**Branch B — honestly disabled.** The route renders an explicit disabled state, never a blank,
a mock, or a quiet stub:

- Layout mirrors `QueryErrorState` variant A's geometry (centered, `max-w-md`, `py-12 px-4`)
  with the honest-disable vocabulary: existing lucide icon (`BarChart3`) 32px `text-ink-mute`
  in a 64px `bg-surface-raised` circle, heading 16px/600 `text-ink`, body 13px/400/1.5
  `text-ink-mute`. NO retry button (there is nothing to retry), NO `role="alert"`, NO danger
  color. `data-testid="analytics-disabled-state"`.
- Copy: NEW keys `analytics:disabled.title` / `analytics:disabled.description` in BOTH locale
  files in the SAME commit (see Copywriting Contract), colon-form addressed.
- Nav handling of the disabled route defers to P97 (reachability is its domain); the plan
  records that deferral (D-03). This contract governs only what the route renders.

Either branch: the `AnalyticsPreviewOverlay` component and `generateSample*` generators stop
rendering on this route. Whether the dead code is deleted or merely unreferenced is planner
discretion; the visual contract is that no fabricated visual reaches the DOM.

### 2. DEAD-06 — `/custom-dashboard` chart + truthful trends (D-04)

**Seam:** `routes/_protected/custom-dashboard.tsx` → `pages/custom-dashboard/CustomDashboardPage.tsx`
→ `components/dashboard-widgets/*` (`KpiWidget.tsx` renders value + trend + sparkline). The
page already wires `QueryErrorState`. Zero visual redesign; two truth deltas:

- **The chart renders.** The data path queries `calendar_entries.event_date` (verified [V] —
  NOT `start_datetime`); the widget chart region shows real rows. Chart chrome as shipped:
  recharts, flat fills, no gradients, `var(--line)` grid.
- **Trend deltas render ONLY from completed comparison requests.** The `KpiWidget` trend row
  (direction arrow + percentage + "from last period") renders when — and only when — the
  comparison request settled successfully with real data. If the comparison aborted, failed, or
  never ran, the trend row is ABSENT (omitted entirely). "0.0%" derived from an aborted request
  is the confident-lie class and is a forbidden shape (D-04, ACCEPTANCE condition 8). An absent
  trend row is the honest render of an unknown delta; no placeholder value, no em-dash
  masquerading as data.
- Widget-level query failures render the inline error contract (variant B) per failed widget;
  succeeded siblings render normally. Loading skeletons neutral, as shipped.
- Percentages and counts format through `lib/format-locale` (Latin digits in BOTH locales by
  policy — not a defect, no fix "repairs" it).

### 3. DEAD-07 — the calendar family (D-05)

Four surfaces, zero redesign; the contract is that each renders truthfully:

**`/calendar`** (`routes/_protected/calendar.tsx` → `components/calendar/UnifiedCalendar`):

  correctly-padded cells), never a blank region, an error state, or an infinite spinner.
- Day cells and event rows obey existing chrome: `1px solid var(--line)`, `--surface`, radii
  from tokens, row hover fades to `--line-soft`. Today's marker keeps its shipped accent
  treatment (part of the accent budget, as shipped).
- Query failure → `QueryErrorState` (variant A for the page's primary query); loading = the
  existing spinner, only while loading. `calendar_entries` is canonical; `calendar_events` is a

**`/calendar/new`** (`routes/_protected/calendar/new.tsx`): the create form MOUNTS with its
existing form chrome (labels, inputs, `.btn-primary` submit as shipped). Reachability +

`14:30 GST` per house format.

**`/events`** (`pages/Events.tsx`): the month grid pads by the REAL weekday offset of the
month's first day — cell 1 sits under its true weekday column — with WORKING month navigation
(previous/next). Nav chevrons flip in RTL (`className={isRTL ? 'rotate-180' : ''}`); weekday
headers keep table-column-header treatment (the one permitted UPPERCASE/mono context). Grid
chrome per the tokens above.

**`/word-assistant`** (`pages/word-assistant/WordAssistantPage.tsx:292-299`): the status badge

The shipped pill chrome is kept (rounded-full, dot + label) and gains a truthful third state:

| Probe state  | Pill                                      | Dot            | Label key                                    |
| ------------ | ----------------------------------------- | -------------- | -------------------------------------------- |
| in flight    | `bg-surface-raised text-ink-mute`         | `bg-ink-faint` | `wordAssistant.checking` (NEW, both locales) |
| connected    | `bg-success/10 text-success` (as shipped) | `bg-success`   | `wordAssistant.connected` (EXISTS)           |
| disconnected | `bg-danger/10 text-danger` (as shipped)   | `bg-danger`    | `wordAssistant.disconnected` (EXISTS)        |

The badge NEVER defaults to connected or disconnected before the probe settles — rendering

- The INSERT-gap fix (trigger timing) is a migration with zero pixels; after it, past-due

- Overdue cards continue to bucket per the shipped `resolveBoardStage` (Todo for commitments

The 93-UI-SPEC transition contract applies verbatim to `/analytics`, `/custom-dashboard`, the
calendar family, `/scenario-sandbox`, and every COUNT-01 surface:

AppShell render-time read to replace (`frontend/src/components/layout/AppShell.tsx`):

```tsx
function readDocumentDir(): 'ltr' | 'rtl' {
  if (typeof document === 'undefined') return 'ltr'
  return document.documentElement.dir === 'rtl' ? 'rtl' : 'ltr'
}
// ...
const isRTL = readDocumentDir() === 'rtl' // line ~123, drives HeroUI Drawer physical placement
```

Why it must change in THIS plan: today DesignProvider.setLocale writes `document.dir` synchronously in the click handler, so AppShell's render-time read is fresh. Once this plan moves the write into DirectionProvider's `useLayoutEffect`, AppShell's render (triggered by the same `languageChanged` batch via `useTranslation`) runs BEFORE the layout effect and reads the OLD dir — the drawer would open from the wrong physical edge after a live toggle. The Radix context is set during the provider's render, so a context read is same-commit fresh. `useDirection()` from '@radix-ui/react-direction' returns the context value or 'ltr' when no provider is mounted (test-safe default).

Its file-header docstring (lines ~32-38) also claims "LanguageProvider keeps the DOM and the i18n runtime in lockstep in production" — stale after this plan; the owner is DirectionProvider.

Radix probe API for the unit test: `import { useDirection } from '@radix-ui/react-direction'` returns the context value ('ltr'|'rtl'|undefined).

Retained pre-paint setter (DO NOT TOUCH): `frontend/public/bootstrap.js` sets html lang/dir from `id.locale` before stylesheets parse. Its byte-match invariant with `tokens/directions.ts` is a phase constraint.

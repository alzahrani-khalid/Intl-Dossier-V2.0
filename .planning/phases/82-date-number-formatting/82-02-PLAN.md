Import surface (established by plan 82-01 — use directly, no exploration needed):

```typescript
import { formatDayFirst, formatDayFirstYear, formatTime, formatDateTime } from '@/lib/format-date'
// formatDayFirst(d)      → 'Tue 28 Apr'          — near-term dates, list rows, chips
// formatDayFirstYear(d)  → '28 Apr 2026'         — archival dates (current options include year)
// formatTime(d)          → '14:30 GST'           — replaces toLocaleTimeString
// formatDateTime(d)      → 'Tue 28 Apr 14:30 GST' — replaces date+time toLocaleString combos
import { toFormatLocale } from '@/lib/format-locale' // for NUMBER formatting locales only
```

Helper-selection rule (apply mechanically per site): current options include `year` →
`formatDayFirstYear`; site renders time only → `formatTime`; site renders date+time in one string
→ `formatDateTime`; chart axis tick/tooltip → date-fns `format(d, 'd MMM')`; everything else →
`formatDayFirst`. All existing locale arguments/ternaries (`isRTL ? 'ar-SA' : 'en-US'`, local
`locale` vars, `toFormatLocale(...)`) are DELETED at date sites — the helpers take the date alone.
Output is byte-identical in en and ar (Pitfall 6: do NOT localize month names for AR).
</interfaces>

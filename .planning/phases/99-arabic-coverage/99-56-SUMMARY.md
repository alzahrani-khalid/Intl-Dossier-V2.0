# P99-56 Summary — whole-key static literal collections

## Result

The classifier now accepts the measured shape: a variable holding the whole key, bound from a member
of a static literal collection. The in-file form traces the whole-key variable through the left branch
of a trailing logical-or expression into a module-level object literal. The cross-module form traces
an element property through `map`, `slice`, `filter`, `useMemo`, `flatMap`, a helper call, and the
literal collection declared by the helper's module. The logical-or right branch remains an unproven
runtime tail and is not added to the closed literal-member domain.

The negative fixtures are load-bearing. A function parameter with no literal-collection producer
remains unclassified, as does a collection mutated by `push` across a module boundary. An ambient or
overload function declaration with no body now returns no trace candidates instead of aborting the
audit. A module-level push is not discarded merely because its source position follows a use inside a
function; mutation ordering is accepted only when the declaration, push, and use share one enclosing
function.

The measured premise remains: the cross-module label collection resolves 27 of 27 in en and 27 of 27 in ar, and the in-file map resolves 8 of 8 in en and 8 of 8 in ar. The motivating population is recorded as premise evidence, not as this task's resolution claim.

This task asserts nothing about the reported residue, the FENCE set, or any profile count; P99-49 owns that claim.

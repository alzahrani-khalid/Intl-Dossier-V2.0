# Phase 95 — UI Design Contract

> Visual and interaction contract for Phase 95: Routes That Don't Render. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. Sources: `95-CONTEXT.md` (D-01..D-20, all locked),
> `frontend/DESIGN.md` (Linear spec, dark-canonical), `frontend/src/design-system/CLAUDE.md`
> (runtime token engine), `93-UI-SPEC.md` (the inherited state vocabulary), and the shipped
> components under `frontend/src/components/`.

**Scope discipline:** this phase introduces NO new visual language. It makes existing routes
render, or say truthfully why they can't, using the state vocabulary Phase 93 shipped. No new
pages, no new navigation chrome, no new layouts, no new button variants, no new Alert variants,
no redesign of any surface it touches. Linear dark is the only direction;
`frontend/design-system/inteldossier_handoff_design/` is historical reference (superseded
2026-07) and nothing here points at it.

Eight requirements; per requirement, the UI contract is narrow and named:

| #   | Requirement                   | Decision | UI contract in one line                                                                                                           |
| --- | ----------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1   | DEAD-01 `/search`             | D-03     | Results render truthfully for typed queries AND suggestion chips; server error → P93 error state, never an empty-results lie      |
| 2   | DEAD-02 `/tasks/queue`        | D-04     | The existing queue page renders against the deployed function; loading / error / empty / populated are four distinct states       |
| 3   | DEAD-03 `/scenario-sandbox`   | D-05     | Backend 500 renders `QueryErrorState` (variant A) — never pixel-identical to the loading spinner                                  |
| 4   | DEAD-04 `/monitoring`         | D-06     | The SPA page mounts (not raw proxy JSON) and its data loads; no visual redesign (RULING-P95-01: keep + narrow proxy)              |
| 5   | DEAD-08 positions/legislation | D-07     | One owner per slot; positions `approvals`/`versions` children drive URL-driven tabs; legislation detail reachable via `<Outlet/>` |
| 6   | DEAD-09 report generation     | D-08     | Generate flow states pending / completed-with-url / failed render truthfully; `generate.unavailable` stays the only fallback      |
| 7   | NOTFOUND-COMPONENT-01         | D-09     | Enforcement (lint/gate) work — zero pixels; the visible invariant is not-found ≠ error, inherited from 93-UI-SPEC                 |
| 8   | RETENTION-CAST-01             | D-10     | Real policy rows render; "No policies" appears ONLY over a truthful empty array; error → error state, never empty                 |

**The inherited state vocabulary is binding.** The four-way discriminator table from 93-UI-SPEC
governs every surface this phase touches — restated because every contract below leans on it:

| State     | Semantic color                                 | Icon               | Announcement   | Primary affordance        |
| --------- | ---------------------------------------------- | ------------------ | -------------- | ------------------------- |
| Empty     | neutral (`--ink-faint`)                        | contextual         | none           | create/CTA (existing)     |
| Error     | danger (`--danger`)                            | `AlertCircle`      | `role="alert"` | Try again (retry)         |
| Not-found | neutral (`--ink-mute`)                         | none (404 numeral) | none           | Go back / Dashboard (nav) |
| Loading   | neutral (`--surface-raised` shimmer / spinner) | none               | none           | none                      |

Rendering one of these states when the truth is another is the confident-lie class this
milestone exists to kill (D-03, D-10).

## Component Contracts

### 1. DEAD-03 — `/scenario-sandbox` error state (D-05)

**Closest existing component:** `components/error-states/QueryErrorState.tsx` — the one shared
query-error state Phase 93 extracted (`role="alert"`, bilingual envelope support,
internal-string-free). This surface REUSES it; building bespoke error markup here is the defect
class 93 closed.

- **Page-level primary query failure → `QueryErrorState` variant A** replacing the scenarios
  region: centered, `AlertCircle` 32px `text-danger` in a 64px `bg-danger/10` circle, heading
  16px/600 `text-ink`, body 13px/400/1.5 `text-ink-mute`, one `.btn-primary` "Try again" wired to
  `refetch()`. Wrapper `role="alert"`, `data-testid="query-error-state"`.
- The current bespoke branch at `routes/_protected/scenario-sandbox.tsx:312-323` (inline Alert
  with a HARDCODED English "Retry" literal and legacy `text-primary`/`text-muted-foreground`
  classes) is replaced by the shared component in the same task — the hardcoded literal and the
  legacy classes do not survive.
- **Loading renders ONLY while `isLoading`** (initial fetch, no cached data): the existing
  spinner or at most 3 `SkeletonCard`s. The instant the query settles `isError`, the error state
  replaces it — no intermediate empty render. Retry policy bounds spinner duration: no retry on
  4xx; at most 2 retries on 5xx/network (the 93-UI-SPEC transition contract, inherited verbatim).
  A backend 500 is therefore never pixel-identical to loading: spinner (neutral, no
  `role="alert"`) vs danger + `AlertCircle` + `role="alert"` + retry button.
- Section-scoped failures (comparison panel) use variant B (inline `Alert` destructive,
  `.btn-ghost` retry, `data-testid="query-error-inline"`); succeeded siblings render normally.
- Copy: the shared component's existing `common:errors.queryFailed.*` keys (already in both
  locales). Any NEW key this surface needs lands in `src/i18n/en/scenario-sandbox.json` AND
  `src/i18n/ar/scenario-sandbox.json` in the SAME commit, addressed colon-form
  (`t('scenario-sandbox:…')`) — dot-form namespace addressing leaks raw keys (D-05, P94 D-10).

### 2. DEAD-01 — `/search` truthful results (D-03)

No new visual design. The contract is state truthfulness:

- A typed query and EACH of the page's own suggestion chips render the real result set — no
  `Cannot read properties of undefined (reading 'forEach')`.
- **Forbidden shape:** an optional-chain guard (`?.forEach`) that renders the empty-results
  state over a server error. Empty renders ONLY when the server truthfully returned zero
  results; a rejected/malformed response renders `QueryErrorState` (variant A when the page's
  primary query failed; variant B for a failed section) with retry.
- Result rows/cards keep their existing chrome: `1px solid var(--line)` borders, `--surface`,
  `var(--row-h)` for any list rows, no shadows, no gradients. Zero-result empty state reuses the
  existing `EmptyState` vocabulary and existing search-namespace copy; this phase adds no new
  empty-state design.

### 3. DEAD-02 — `/tasks/queue` renders (D-04)

The missing half is DEPLOYMENT of `assignments-queue`; the UI contract is that the existing page
(`pages/AssignmentQueue.tsx` — already a named Phase 93 error-state surface) shows four distinct
states once the function answers:

- **Loading:** one composed `SkeletonTable` capped at 8 rows (`components/ui/skeleton.tsx`),
  neutral shimmer on `--surface-raised`.
- **Error:** `QueryErrorState` variant A (the P93 retrofit stands; no `error.message` in JSX).
- **Empty:** the existing `EmptyState` vocabulary — only over a truthful empty queue.
- **Populated:** queue rows obey `var(--row-h)`; row hover fades to `--line-soft`, never lifts.

No visual redesign of the queue itself.

### 4. DEAD-04 — `/monitoring` mounts (D-06, RULING-P95-01)

The route is KEPT; the proxy stops claiming the bare `/monitoring` prefix. **The UI contract is
only that the SPA page (`routes/_protected/monitoring.tsx` → MonitoringDashboard) mounts inside
the app shell and its data loads** — a navigation to `/monitoring` renders React, never raw proxy
JSON. Its own query failures follow the inherited error contract (variant B per failed widget,
succeeded siblings unaffected). No visual redesign, no layout change, no new chrome — the three
ruling conditions (mechanical API-call enumeration, `deploy/` nginx check, decision recording)
are plan/infra work with zero pixel delta.

### 5. DEAD-08 — positions/legislation slots and URL-driven tabs (D-07)

**Closest existing tab component (cited per contract requirement):**
`frontend/src/components/ui/tabs.tsx` — the `Tabs`/`TabsList`/`TabsTrigger`/`TabsContent`
re-export of `heroui-tabs.tsx` (HeroUI v3 visuals, token-bound), used today by
`routes/_protected/positions/$id.tsx:124`. **That exact primitive is the visual; nothing about
the tab appearance changes.** The delta is the STATE SOURCE:

- Active tab derives from the matched child route (`approvals` / `versions` under the surviving
  positions param slot), not from local `defaultValue` state. Selecting a tab navigates
  (TanStack `Link`/`useNavigate` driving the `Tabs` `value`); tab content renders via the child
  route. Deep-linking `/positions/:id/approvals` opens with that tab active; browser back moves
  tab state; the tab strip does not remount the page header.
- Which param file survives (`$id.tsx` vs `$positionId.tsx`) is planner discretion (D-07); the
  visual contract is invariant under that choice. Every inbound `Link`/`useNavigate` target is
  swept in the same edit — a stale link that 404s a working page is a rendering regression.
- `legislation.tsx` renders `<Outlet/>` so the existing legislation detail page mounts —
  reachability only, zero visual delta to the detail page itself.
- Tab triggers keep sentence case, no icons added, no counts added. Focus ring in `--accent`
  per the shipped recipe. RTL: tab order follows logical flow automatically (the primitive is
  logical-property based); no directional icons exist in the strip, so no flip case.

### 6. DEAD-09 — report generation states (D-08)

When generation becomes real, the generate flow renders three truthful states; the honest
terminal state remains the ONLY fallback (rename-never-ships-alone law, RULING-P94-04):

- **Pending:** the generated-report entry renders a pending row — label from
  `report-builder:generate.pending`, neutral (`text-ink-mute`), mono-formatted timestamp per the
  house date format (`Tue 28 Apr`, `14:30 GST`). The generate button is disabled while a job is
  in flight (`aria-disabled`, label unchanged — no spinner redesign).
- **Completed-with-url:** the entry renders the report row with an "Open report" action styled
  `.btn-ghost` (accent is NOT spent here — the row lives inside a card; ghost keeps the accent
  budget intact). The action opens the REAL artifact url the server returned. A completed entry
  without a url is a contract violation, never rendered as success.
- **Failed:** danger vocabulary — `AlertCircle` + `text-danger` + `role="alert"` on the entry's
  status, label from `report-builder:generate.failed`, with retry offered via the page's
  existing generate affordance. No raw `error.message` reaches JSX (P93 copy rule).
- **Unavailable (terminal fallback):** the existing `report-builder:generate.unavailable`
  rendering ships unchanged (EN "Report generation is unavailable" / AR
  "إنشاء التقارير غير متاح" — both already in the locale files). If the chosen backend path
  cannot return a real url, this state stays; fabricating a completed entry is the forbidden
  shape.
- The client pin `frontend/src/pages/reports/__tests__/generate-entry.test.ts` is updated in the
  SAME task that changes `generate-entry.ts` behaviour (C9b, D-08).

### 7. NOTFOUND-COMPONENT-01 — enforcement, zero pixels (D-09)

Lint/gate work. The only user-visible invariant this contract records: a well-formed-but-absent
record reaches the root 404 page (oversized numeral, neutral, navigational — the shipped
`NotFoundPage`), NEVER the router's "Something went wrong" error component. Not-found and error
remain visually distinct per the inherited discriminator table. No new component, no copy, no
styling.

### 8. RETENTION-CAST-01 — real rows, no confident lie (D-10)

No new UI. The `/admin/data-retention` table renders the policy rows the server sent, obeying
`var(--row-h)`; the "No policies" empty state renders ONLY over a truthful empty array; a
malformed/rejected response renders `QueryErrorState` (the P93 retrofit on this route stands).
**Forbidden fix shape: `Array.isArray(x) ? x : []`** — it renders empty over server-sent rows
(D-10, REQUIREMENTS.md:336).

## Loading → Error Transition (inherited, binding on every surface above)

The 93-UI-SPEC transition contract applies verbatim to `/search`, `/tasks/queue`,
`/scenario-sandbox`, `/monitoring` widgets, the positions/legislation details, the report list,
and data-retention:

- Skeleton/spinner renders only while `isLoading`; `isError` replaces it immediately — no
  confident-empty flash.
- At most ONE composed skeleton per region (`SkeletonTable` ≤ 8 rows or ≤ 3 `SkeletonCard`s).
- No retry on 4xx (a 404 resolves in single-request time); at most 2 retries on 5xx/network.
- Skeletons stay neutral (`--surface-raised` shimmer) — never previewing danger color.

## RTL & Responsive Contract

- Logical properties only (`ms-*`, `ps-*`, `start-*`, `text-start`) — ESLint errors on physical
  classes. The shared error component and the Alert/Tabs recipes are already logical; reuse
  inherits compliance.
- `AlertCircle` is symmetric — no flip. If any surface this phase makes render exposes a
  directional chevron (tab overflow, report row affordance), it flips via
  `className={isRTL ? 'rotate-180' : ''}`.
- Every state in this contract renders under `dir="rtl"` with Tajawal applied (`?lng=ar` flips
  at first paint for visual checks). Pixel RTL sign-off remains an OPERATOR park (ORCH-BRIEF §3)
  — the contract requires the render, not the sign-off claim.
- Desktop-primary: build at 1280px, verify at 1024px and 1400px. Tab strips and error states
  center/flow within the content region at both; inline states never overflow their card. Below
  768px the app is read-only; retry buttons meet the 44px touch target there via the existing
  `min-h-11` mobile pattern.
- SLA/mono tokens that appear on made-to-render surfaces stay LTR-isolated in Arabic
  (`dir="ltr"` spans), per `frontend/DESIGN.md` §RTL cascade.

## Verification Notes (for planner/executor oracles)

- Loading vs error is DOM-distinguishable on every surface: neutral spinner/skeleton (no role)
  vs `role="alert"` + `data-testid="query-error-state"`/`"query-error-inline"` + `text-danger`
  icon. Criterion 3's "never pixel-identical" is assertable without pixel diffing.
- Forced errors via CDP `Network.setBlockedURLs` (browser-harness; claude-in-chrome and
  playwright-MCP do not attach). RLS denials read as empty 200s — assert `role="alert"` via DOM,
  never infer from emptiness (D-13).
- URL-driven tabs: assert `/positions/:id/approvals` deep-link renders the approvals panel with
  that trigger active (`aria-selected="true"` on the HeroUI trigger), and browser back returns
  to the prior tab.
- `/monitoring` oracle: response `content-type` is HTML and the mounted page renders a known DOM
  node — never `application/json` at the route.
- Report generation: a `completed` entry in the DOM implies a real `url` attribute/href; the
  test pin `generate-entry.test.ts` is the C9b consumer updated in the same task.
- Retention: with the real `{data:[...]}` envelope mocked at N rows, the table renders N rows;
  the empty state appears only for `{data:[]}`; a bare-array or malformed body renders the error
  state.
- No rendered text matches a PostgREST/Postgres code pattern (`42501`, `42703`, `42P01`),
  `supabase`, `select`, or a stack-frame shape on any surface this phase touches.

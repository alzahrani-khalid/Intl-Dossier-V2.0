<objective>
Close DEAD-01 (success criterion 1): `/search` returns results for a typed query and for each of
its own suggestion chips, with no `Cannot read properties of undefined (reading 'forEach')`.

Root cause (probe-verified 2026-08-16): the deployed `search` fn returns
`{data, count, limit, offset, query, took_ms, warnings, metadata}` — no `dossiers` key — while
`useDossierFirstSearch.ts:109` runs `searchQuery.data.dossiers.forEach(...)`. The fix is the
CONTRACT, at the repository seam (D-03). FORBIDDEN FIX SHAPE, named per ACCEPTANCE-P95 condition
8: a `?.forEach` or `|| []` guard at the crash site that renders an empty result set over a live
server response — the confident-lie class. Any diff touching only the `typeCounts` memo is the
Pitfall-1 shape and is a REJECT.

Chosen mechanism (research recommendation, options 1+2): repository envelope adapter for
dossiers + a second request to the DEPLOYED `quickswitcher-search` fn for real `related_work`.
No server deploy in this plan. Named omission: the deployed `search` fn's stale `validTypes`
(still contains 'theme') is NOT fixed here — a `types=topic` filter 400s, which renders the
error state truthfully; recorded in the SUMMARY and the closing register, deferred to whichever
phase next deploys `search`.

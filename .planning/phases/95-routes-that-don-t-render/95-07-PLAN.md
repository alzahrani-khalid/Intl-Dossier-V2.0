<objective>
Close NOTFOUND-COMPONENT-01 (filed-finding close, D-09 default branch: ADD): a bare `notFound()`
thrown from a COMPONENT never reaches the root 404 page in @tanstack/react-router@1.170.8 — it
reaches the defaultErrorComponent ("Something went wrong"). Traced by 93-12, filed, and until
this phase enforced nowhere.

Research settled the mechanics: esquery cannot express "not inside a loader property" (no
ancestor-negation combinator), so a `no-restricted-syntax` selector would false-positive on the
correct bare loader throw — failing D-09's negative control. The ~40-line custom rule in the
existing flat config CAN: compliant = first arg is an ObjectExpression containing a `routeId`
property; walk `node.parent` — an ancestor Property keyed `loader`/`beforeLoad` exempts the
bare form; otherwise report. `notFound({ global: true })` (the deprecated spelling) is
non-compliant.

Zero pixels. The user-visible invariant (not-found ≠ error) is inherited from 93-UI-SPEC.

Output: rule module + registration + committed positive-control fixture + both controls observed.
</objective>

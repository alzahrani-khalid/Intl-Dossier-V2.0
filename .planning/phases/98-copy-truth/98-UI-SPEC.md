**Scope discipline — this phase changes STRINGS, not layouts.** It rewrites copy, authors
missing i18n keys, routes date rendering onto the existing shared formatter, localizes one
global toast, and deletes ONE render guard. No new page, no new component, no new layout, no
new button variant, no motion, no restyle. **The single render-behaviour change in the phase:**
`DossierTypeStatsCard.tsx:168` currently withholds the Elected Officials type-guide popover
behind `type !== 'elected_official' &&`; criterion 7 deletes that guard in the same change that
lands five `dossier:` keys (D-12, atomic), so an existing popover component starts rendering
for a ninth case. That popover is the one surface in this contract that needs a real visual
contract; everything else is a contract about _how changed copy must render_ inside shipped
chrome. Linear dark is the only direction. The prototype at
`frontend/design-system/inteldossier_handoff_design/` is historical reference (superseded
2026-07) and nothing here points at it.

**Checker note (binding):** where `gsd-ui-checker`'s pre-baked rules (the max-4-font-sizes rule,
the typography/spacing pre-bake expectation) disagree with `frontend/DESIGN.md`, **DESIGN.md
wins**. The Typography and Spacing sections below are pre-baked explicitly and scoped to what
this phase AUTHORS — which is zero new type and zero new spacing — so the declared bounds are
checkable without distorting the design system.

### Criterion 7 / COPY-08 — the Elected Officials type-guide popover (the one real visual contract)

**Render path is fixed: the popover renders through `DossierTypeGuide` (popover variant) and
`ui/popover.tsx` byte-unchanged.** Deleting the guard at `DossierTypeStatsCard.tsx:168` (and its
`:160-167` comment block) makes the ninth case render through exactly the chrome the seven
siblings already render. No component edit for style, no new wrapper, no bespoke EO treatment.

**Chrome (inherited, recorded — not re-authored by this phase):**

- Trigger: the existing help button — `hidden sm:inline-flex`, `min-h-5 min-w-5 p-0.5`,
  `rounded-full`, `bg-[var(--surface)]` hover `--accent-soft`, `HelpCircle h-3 w-3`, focus ring
  `--accent`. Desktop-only by construction (`hidden` below `sm`); this phase does not change
  that.

  `w-80 sm:w-96` (320px → 384px), `p-4`; primitive chrome from `ui/popover.tsx:35` =
  `bg-[var(--surface-raised)]`, `1px solid var(--line)`, `rounded-[var(--radius)]` (8px),
  `shadow-[var(--shadow)]` plus the guide's own `shadow-lg`. **Observed divergences from
  DESIGN.md** (popovers nominally sit on `--surface-3`, shadowless; this one sits on
  `--surface-raised` with shadow, and its internal color classes are legacy
  `text-muted-foreground` / `text-success` / `text-warning` utilities): these ship today on all
  seven siblings. **"Identical to the siblings" is the contract; repairing the primitive is NOT
  this phase.** Recorded here so a later owner does not rediscover it.
- Section anatomy (top to bottom): header (icon chip + `type.elected_official` title 16px/600 +
  `typeDescription.elected_official` 14px muted), When-to-use (Lightbulb + label + `ps-6` body),
  Examples (Check + label + Badge chips), Common links (Link2 + label + `ArrowRight` rows,
  arrow rotates 180° in RTL), Separator, Not-for (X + warning-toned label + body). All logical
  properties already (`ps-6`, `me-1`, `text-start`).

**Content contract (what the five authored keys must satisfy):**

| Key (`dossier:` ns, BOTH locales, same commit) | Shape      | Bound                                                                                       |
| ---------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------- |
| `typeDescription.elected_official`             | string     | one sentence, ≤ ~110 chars EN; register matches the seven sibling descriptions              |
| `typeGuide.elected_official.whenToUse`         | string     | 1–2 sentences, ≤ ~160 chars EN (≈2 wrapped lines at `sm:w-96`)                              |

### Criterion 1 / COPY-07 — display labels in place

- **Stats-card label** (`DossierTypeStatsCard.tsx:228`): `"% of total active dossiers"` routes
  through `t()`. **EN value stays byte-identical** (it already obeys voice law) so the EN render
  is pixel-unchanged; the AR value is new. It renders in the same element — 10px/500 (`sm:` 12px),
  `--ink-mute`, centered, block — which wraps naturally: the AR string must hold ≤ 2 wrapped
  lines at the card's narrowest rendered width (the 1024px grid), ≤ ~45 chars. Recommended AR
  default: `النسبة من إجمالي الملفات النشطة` — the word for "dossier" follows whatever term
  `ar/dossier.json` already dominates with (glossary unification is P99). No truncation, no
  fixed height, no new classes. Key name is planner discretion (recommend
  `dossier:typeStats.percentOfActive`).
- **Enum labels** (COPY-01 population): each repair swaps the string only — the display label
  renders in the SAME element, position, and classes the raw value occupied (chip, cell, badge,
  or span; all size by content). No new chips, no new badge variants, no central label
  registry (house pattern is per-namespace enum-keyed `t()` families). Sentence case; the
  work-item Priority family renders **Urgent**, never Critical; the intake `urgency` family
  legitimately renders **Critical** (distinct enum — the CLAUDE.md carve-out; values map to
  labels, columns are never renamed).
- **Week header** (`EngagementsList.tsx:142-145`): the rendered group header contains no ISO
  token (`2026-W27`); its prefix localizes via `t()` and any date inside it obeys the day-first
  shape from `lib/format-date.ts`. Exact wording/mechanism is planner discretion; the rendered
  bound is not.

### Criterion 5 / COPY-05 — the date/time typographic contract

- **One source:** every routed surface renders through `lib/format-date.ts` —
  `formatDayFirst` → `Tue 28 Apr`, `formatTime` → `14:30 GST`, `formatDayFirstYear` →
  `28 Apr 2026`, `formatDateTime` → composition; em-dash `—` for null/invalid. Output is
  **Latin and byte-identical in both locales** (Policy D, Phase 82 — Latin digits in Arabic are
  deliberate; do not "fix" them).
- **Dates are BODY text** (13px/400 in table cells and meta positions as shipped), **never
  mono** — JetBrains Mono stays reserved for SLA windows (`T-3`/`T+2`) and keyboard hints. Do
  NOT introduce `tabular-nums`, mono styling, or any new CSS for dates this phase: the
  formatter's `2-digit` day + fixed short-month shape already yields near-uniform column widths.
- **No wrapping mid-format:** a date or time token renders on one line at 1024px and 1400px in
  the cells and chips it lands in. The strings are short; if a wrap is ever observed, the remedy
  is the shipped cell's existing nowrap treatment, not new styling.
- **RTL:** inside Arabic sentences the Latin date/time tokens render as single LTR bidi runs —
  the formatter emits standalone tokens and this phase adds **no new `dir` isolation spans**
  (the existing LTR isolation on SLA mono tokens is shipped chrome, unchanged). The oracle
  observes the rendered shape under `?lng=ar`.
- **Sanctioned relative time** (D-25): feed/timeline recency surfaces ONLY, through one shared
  localized helper in the formatter module — its rendered output is a localized phrase in the
  session language (Arabic words under `ar`, Latin digits per policy). Every other
  `formatDistanceToNow` site migrates to the day-first shape. `MMMM yyyy` calendar-grid month
  headers are navigation chrome, OUT (their Arabic rides Phase 99).
- **`Fill with Mock Data`** (D-26): no rendered surface changes in production — the button never
  rendered there; the key is deleted from both locales and the label inlined in the DEV-gated
  block. Dev builds keep the affordance; the claim closes on the BUILT bundle, not a pixel.

## RTL & Responsive Contract

- Logical properties only (`ms-*`, `me-*`, `ps-*`, `start-*`, `text-start`) — ESLint ERRORS on
  physical classes. Every component this phase renders through is already compliant (`ps-6`,
  `me-1`, `text-start`, `ArrowRight` rotate-180); string-only changes cannot break it, and the
  one code deletion (the guard) removes JSX rather than adding any.
- Every newly-authored `ar` string renders under `dir="rtl"` with Tajawal applied (`?lng=ar`
  flips at first paint — the oracle mechanism). Latin date/time tokens and Latin digits inside
  Arabic copy are policy, not defects.

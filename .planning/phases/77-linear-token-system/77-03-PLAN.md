<planner_decisions>
Decisions resolved by the planner (from RESEARCH §Open Questions, within CONTEXT "Claude's Discretion"):

- **Q1 hue axis:** ADOPT the researcher recommendation. The accent family becomes palette literals (verbatim `#5e6ad2` cannot be reproduced by the `oklch(58% 0.14 h)` formula at any h). The SLA family is pinned to Linear-band literals (derive at the accent hue ≈275, store as literal strings). The hue slider UI is retired in 77-05; hue plumbing (`id.hue`, `useHue`, BuildInput.hue) is removed in 77-07. In THIS plan, buildTokens keeps the `hue` parameter and legacy hue-math as the fallback for the four legacy directions only.
- **Q2 --shadow-card:** keep the token name, value `'none'` for linear (Linear = no card shadows); legacy directions keep the current literal. Removal of the token would risk unset-var fallout at consumers.
- **Hairline mapping (deviation from STACK.md, flagged by research §Linear reference "Naming caution"):** STACK.md maps `--line-soft: #34343a` (hairline-strong), which INVERTS the engine semantic (`--line-soft` is everywhere consumed as the SOFTER divider). Decision: `--line` = hairline `#23252a`; `--line-soft` = a DERIVED value perceptibly softer than `--line` against surface-1 (executor derives in-band); the verbatim `#34343a` lands as a NEW token `--line-strong` (hairline-strong) used by the 77-06 re-skin recipes. All verbatim reference values still land; document this mapping in the SUMMARY (77-08 writes it into DESIGN.md).
- **Unmapped verbatim extras:** `hairline-tertiary #3e3e44`, `semantic-overlay #000000`, `brand-secure #7a7fad` are NOT emitted as tokens in this phase (no consumer). Record them in the SUMMARY so DESIGN.md can list them as reserved.

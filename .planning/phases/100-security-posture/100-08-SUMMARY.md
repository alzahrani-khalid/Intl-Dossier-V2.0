# P100-08 Summary — function `search_path` pinning

Every non-extension function in `public`, `read_models`, and `events`, except the same 35 functions
that already carried intentionally different settings at phase HEAD, now has the schema-approved explicit
`search_path`. The live, post-P100-17 population is 592, so the derived positive target is
`592 - 35 = 557`: 557 approved, the original 35 elsewhere, and zero unpinned.

P100-17 converted six functions that were in the phase-HEAD unpinned population and added one new
function. It pinned all seven to `search_path=public`. Therefore the live unpinned count for this task
was `548 - 6 = 542`, while the population grew from 591 to 592. The migration contains the 542
catalog-generated statements plus seven explicit normalizations from `public` to the approved
`public, pg_temp`; it does not modify the original 35-function bucket.

The literal generator was:

```sql
select format('ALTER FUNCTION %s SET search_path = %s;', p.oid::regprocedure,
              case when n.nspname = 'public' then 'public, pg_temp'
                   else quote_ident(n.nspname) || ', public, pg_temp' end)
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname in ('public','read_models','events') and p.prokind = 'f'
  and not exists (
    select 1 from unnest(coalesce(p.proconfig,'{}')) x
    where x like 'search\_path=%'
  )
  and not exists (
    select 1 from pg_depend d where d.objid = p.oid and d.deptype = 'e'
  )
order by 1;
```

`supabase/migrations/20260908000008_p100_function_search_path_pin.sql`.

## Three policy-function schema checks

The bodies were read live with `pg_get_functiondef` before pinning (command exit status 0).

- `public.is_assigned_to_dossier(uuid)` reads the unqualified `dossier_owners` table, which resolves
  from `public`, and calls the explicitly-qualified `auth.uid()`, which resolves from `auth`.
  `search_path=public, pg_temp` covers the unqualified public table. The auth object is schema-qualified,
  so it does not need `auth` in the search path and continues resolving exactly as before.
- `public.get_user_units(uuid)` reads the unqualified `user_units` table from `public` and uses
  PostgreSQL built-ins/types such as `coalesce`, `array_agg`, `now`, `text[]`, and ordering
  semantics from implicitly searched `pg_catalog`. The approved path covers `public`; PostgreSQL
  searches `pg_catalog` implicitly, so all objects it actually resolves remain covered.
- `public.check_user_is_contributor(uuid,uuid)` reads the unqualified `task_contributors` table from
  `public` and uses SQL/boolean machinery from implicitly searched `pg_catalog`. The approved path
  covers the public relation and preserves the built-in resolution.

The relevant verbatim definitions were:

```sql
CREATE OR REPLACE FUNCTION public.check_user_is_contributor(task_uuid uuid, user_uuid uuid)
 RETURNS boolean
 LANGUAGE sql
 STABLE SECURITY DEFINER
AS $function$
  SELECT EXISTS (
    SELECT 1 FROM task_contributors
    WHERE task_id = task_uuid
      AND user_id = user_uuid
      AND removed_at IS NULL
  );
$function$

CREATE OR REPLACE FUNCTION public.get_user_units(p_user_id uuid)
 RETURNS text[]
 LANGUAGE plpgsql
 STABLE SECURITY DEFINER
AS $function$
DECLARE
  units TEXT[];
BEGIN
  SELECT COALESCE(
    ARRAY_AGG(unit_id ORDER BY is_primary DESC NULLS LAST),
    ARRAY['default']::TEXT[]
  )
  INTO units
  FROM user_units
  WHERE user_id = p_user_id
    AND (is_active IS NULL OR is_active = true)
    AND (expires_at IS NULL OR expires_at > NOW());

  RETURN COALESCE(NULLIF(units, ARRAY[]::TEXT[]), ARRAY['default']::TEXT[]);
END;
$function$

CREATE OR REPLACE FUNCTION public.is_assigned_to_dossier(dossier_uuid uuid)
 RETURNS boolean
 LANGUAGE plpgsql
 SECURITY DEFINER
AS $function$
BEGIN
  RETURN EXISTS (
    SELECT 1 FROM dossier_owners
    WHERE dossier_id = dossier_uuid
    AND user_id = auth.uid()
  );
END;
$function$
```
